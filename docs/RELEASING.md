# Как обновлять приложение и поддерживать GitHub

Коротко: **на этом ПК всё делает агент**. Вам не нужно каждый раз заходить в
браузер. GitHub CLI уже авторизован, git настроен, ключ подписи лежит в
проекте. Браузер нужен только при первом входе на новом ПК или если токен
отозван.

## Что где лежит

| Что | Где |
|---|---|
| Исходники | `github.com/MaxKeks88/opencode-android` (ветка `main`) |
| APK для людей | GitHub **Releases** (не в git: 192 МБ) |
| Рантайм opencode/git/python | не в git; `tools/fetch_runtime.py` качает из upstream |
| Подпись | `keystore.jks` + `keystore.properties` — **только локально, не в git** |
| Локальная история git | каталог `.git` вынесен вне Google Drive |

## Один раз на новом компьютере

1. Установить Git, JDK 17, Android SDK (build-tools + platform), Python 3.8+,
   [GitHub CLI](https://cli.github.com/).
2. `gh auth login` → GitHub → вход в браузере (один раз).
3. `gh auth setup-git` — чтобы `git push` работал через gh.
4. Скопировать `keystore.jks` и `keystore.properties` (без них нельзя
   выпускать обновления поверх установленных).
5. `python tools/fetch_runtime.py` — скачать рантайм (~300 МБ).

После этого браузер для рутинных обновлений **не нужен**.

## Выпуск новой версии (что делает агент)

1. **Поднять версию** в `app/AndroidManifest.xml`:
   - `versionCode` +1 (обязательно для установки поверх);
   - `versionName` — semver, например `1.14.0`.
2. **Собрать публичную сборку:** `python build_apk.py --no-debug`
   (без `android:debuggable` и WebView-отладки).
3. **Проверить:** установить на телефон, `python tools/smoke_test.py`,
   пройти основные экраны.
   > `smoke_test.py` читает токен через `run-as` → работает только на
   > **debuggable** сборке. Публичную `--no-debug` проверяйте вручную или
   > держите отдельную debug-сборку для автотестов.4. **Коммит и push:** `git add -A && git commit -m "1.14: ..." && git push`.
5. **Релиз:**
   ```bash
   sha256sum OpenCodeAndroid.apk   # или Get-FileHash на Windows
   gh release create v1.14.0 OpenCodeAndroid.apk SHA256SUMS.txt \
      --title "1.14.0" --notes-file notes.md
   ```
   Для большого APK можно сначала создать черновик, загрузить ассет и затем
   опубликовать:
   ```bash
   gh release create v1.14.0 SHA256SUMS.txt --draft ...
   gh release upload v1.14.0 OpenCodeAndroid.apk
   gh release edit v1.14.0 --draft=false
   ```
   **Имя APK-ассета не менять:** всегда `OpenCodeAndroid.apk`. Апдейтер
   кэширует ссылку на 6 часов; переименование (например,
   `OpenCodeAndroid-1.23.0.apk`) даёт HTTP 404 у тех, кто уже проверял
   обновление. Если переименовать всё же пришлось, замените ассет под старым
   именем или дождитесь следующей проверки у пользователя.
6. Пользователи видят стрелку **⟳** у шестерёнки и обновляются сами.

## Что нужно от вас

- Сказать: «делаем версию X с такими изменениями».
- Проверить приложение на телефоне после сборки.
- Хранить резервную копию `keystore.jks` и паролей **вне GitHub**.
- Решать спорные вопросы по issues/PR (если появятся).

Всё остальное — версии, сборка, тесты, коммиты, теги, релизы, загрузка APK —
делает агент.

## Если браузер всё-таки нужен

- Первый `gh auth login` на новом ПК.
- Токен отозван/истёк: `gh auth login` заново.
- Хотите вручную отредактировать описание релиза, README или issue — можно
  через сайт GitHub, но это не обязательно.
- Ручная публикация без агента: **Releases → Draft a new release →** тег
  `vX.Y.Z`, загрузить APK и `SHA256SUMS.txt`, опубликовать.

## Подпись (критично)

Android разрешает обновление только если новый APK подписан **тем же ключом**.
Поэтому:

- `keystore.jks` и `keystore.properties` не публиковать и не терять;
- если ключ потерян — обновления поверх старых установок невозможны,
  пользователям придётся удалять приложение (данные пропадут);
- `build_apk.py --release` требует свой ключ; `--no-debug` — публичная сборка
  без `debuggable`, но с тем же ключом;
- с 1.14.1 пароль keystore случайный, вне Drive:
  `C:\Users\HomePC\OpenCodeAPK-keys-2026-11-09\PASSWORD.txt`; журнал сборки
  пароли не печатает;
- `gh` установлен, но для новых сессий нужен `gh auth login` (токен из
  git-credential не имеет `read:org`).

## Ограничения GitHub

- Обычный git: файл ≤ 100 МБ → APK и рантайм только в Releases.
- Releases: ассет до 2 ГБ; 192 МБ загружается долго на медленном аплинке.
- Публичный API без токена: 60 запросов/час; приложение кэширует проверку
  на 6 часов, этого достаточно.
- Git LFS не используем: бесплатный трафик 1 ГБ/мес, для публичного APK не
  подходит.

## Если что-то пошло не так

- **`gh: not logged in`** → `gh auth login`.
- **`git push` просит пароль** → `gh auth setup-git`.
- **`INSTALL_FAILED_UPDATE_INCOMPATIBLE`** → APK подписан другим ключом;
  используйте тот же `keystore.jks`.
- **Загрузка релиза зависла** → прервать, повторить `gh release upload ...`;
  при медленном прокси отключить `HTTP(S)_PROXY` для gh.
- **Ошибочный релиз** → `gh release delete vX.Y.Z --yes` (или отредактировать
  на сайте); уже обновившиеся пользователи не смогут откатиться — выпускать
  версию с большим `versionCode`.

## GitHub Actions (опционально, позже)

Можно собирать APK на тег автоматически. Понадобятся:
`ANDROID_SDK_ROOT`, JDK 17, `python tools/fetch_runtime.py` и секреты
`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
Пока не настроено: ручная сборка проще и не хранит ключ в GitHub.
