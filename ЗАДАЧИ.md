## Задача 3. Уведомления — только по завершении полного ответа

### Что не так

Сейчас уведомления приходят несколько раз за один ответ: во время
«раздумий», вызовов инструментов и промежуточных шагов. Должно быть **одно
уведомление**, когда ответ полностью готов, и только если включена галочка
«Уведомления о завершении».

### Причины (точки в коде)

- `RuntimeService.notifyLoop()` (~строка 280): на каждое событие
  `session.execution.succeeded/failed/interrupted` показывает «Ответ готов».
  Один ответ может содержать несколько execution (шаги/инструменты) — отсюда
  несколько уведомлений.
- `Notifications.show()` (~18): не проверяет преф `notify`, поэтому галочка
  в настройках ни на что не влияет.
- `page.html`, `handle()` (~1513): при переходе `busy → idle` тоже вызывает
  `BR.notify(...)`, не глядя на настройку — возможен дубль с нативным
  watcher.

### Что сделать

1. `Notifications.show()`: в начале
   `if (!App.prefs().getBoolean("notify", true)) return;`
   (отдельно решить, что делают `sound`/`vib`).
2. `RuntimeService.notifyLoop()`: вместо немедленного уведомления на каждый
   `succeeded` — отложенное (debounce ~1.5–2 с) на сессию:
   - на `session.execution.started` — отменить отложенное уведомление и
     добавить сессию в `active`;
   - на `succeeded/failed/interrupted` — запомнить «последнее завершение»;
   - через 1.5–2 с проверить `GET /api/session/{id}`: если
     `time.idle >= time.busy` (сессия реально свободна) — показать **одно**
     уведомление; иначе ждать следующего события.
3. `permission.asked` / `form.created`: дедуплицировать по `id` запроса,
   уважать `notify`, не спамить.
4. `page.html`: убрать `BR.notify` при `busy → idle` (нативный watcher уже
   уведомляет) либо явно проверять `readSettings().notify`; оставить только
   вибрацию/звук, когда приложение открыто.
5. Проверить: длинный ответ с 3–5 инструментами → **одно** уведомление в
   конце; галочка выключена → ни одного; приложение открыто → без
   уведомления (только вибрация); в фоне → одно.

### Критерий готовности

За один полный ответ приходит ровно одно уведомление «Ответ готов», и только
при включённой галочке.

## Задача 4. Каталог провайдеров как в официальном приложении (обдумать, потом делать)

### Что есть сейчас

Вкладка «Провайдеры» (`renderProviders()`) показывает только уже
**настроенные** провайдеры из `GET /api/provider` (модели, ключ, вкл/выкл).
Добавить нового провайдера из интерфейса нельзя — только «Ключ OpenCode Zen»
и вход в аккаунт OpenCode.

### Что выяснено (API уже умеет всё)

`GET /api/integration` возвращает **каталог из 239 провайдеров**:
```json
{"id":"anthropic","name":"Anthropic","methods":[{"type":"key"},{"type":"env",...}],"connections":[]}
```
Методы: `key`, `env`, `oauth` (с формой), `external`, `command`.
Подключение:
- ключ: `POST /api/integration/{id}/connect/key` `{"key":"..."}`;
- OAuth: `POST /api/integration/{id}/connect/oauth` `{"methodID":"...","answers":{...}}`
  → `url` → браузер → `GET .../oauth/{attemptID}` → `POST .../complete`;
- `external` / `command` — аналогично.
- Список подключённых: `GET /api/credential`; провайдеры: `GET /api/provider`.

Популярные (по ТЗ): **Anthropic, GitHub Copilot, OpenAI, Google**.
У GitHub Copilot и OpenAI есть OAuth-методы, у Anthropic/Google — ключ.

### Предлагаемый UX

1. В «Провайдерах» сверху блок **«Популярные»**: карточки
   Anthropic · GitHub Copilot · OpenAI · Google (+ OpenCode/OpenCode Go).
2. Кнопка **«Показать больше провайдеров»** → отдельный экран:
   - поиск по имени/id (клиентский фильтр);
   - список 239 провайдеров порциями (по 30–50, «показать ещё»), чтобы не
     тормозил WebView;
   - у подключённых — метка «подключён».
3. Тап по провайдеру → выбор способа:
   - «Вставить API-ключ» → поле + сохранить → `connect/key` → обновить
     `/api/provider` и модели;
   - «Войти» (OAuth) → общий механизм, как сейчас для аккаунта OpenCode:
     открыть URL, дождаться, `complete`.
4. Кэш каталога в `localStorage` на 24 часа; при ошибке — повтор запроса.
5. Иконки: отдельных URL в API нет — рисуем инициалы/эмодзи, без внешних
   картинок.

### Что обдумать перед реализацией

- OAuth-провайдеры (Copilot/OpenAI) требуют формы и браузер — переиспользовать
  текущий `loginStart/loginCode`, обобщив на `integrationID`.
- Где хранить ключи: только в OpenCode (`/api/credential`), не в prefs/HTML.
- Не показывать секреты в логах; маскировать в UI.
- Каталог большой: не рендерить все 239 сразу; поиск + пагинация.
- Проверить, что после `connect/key` модели появляются в списке без
  перезапуска (`/api/model`).

### Критерий готовности

Можно добавить Anthropic по ключу и GitHub Copilot/OpenAI по OAuth прямо из
телефона; «Показать больше» открывает полный список с поиском; после
подключения провайдер и его модели доступны в выборе модели.
