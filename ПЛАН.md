## 1. SSH-клиент для git (✅ сделано)

### Результат
- `ssh`, `ssh-keygen`, `scp`, `sftp`, `ssh-keyscan`, `nc` + библиотеки в
  `runtime/git/`.
- OpenSSH не находит пользователя в `/etc/passwd` → SSH запускается отдельным
  патченным loader-ом (`ssh-lib/ld-musl-aarch64.so.1`, путь `/sdcard/p`),
  Java пишет `/sdcard/p` (uid/home) при старте.
- DNS: `~/.ssh/config` → `ProxyCommand ssh-proxy %h %p`; `ssh-proxy` читает
  `files/.proxy` и запускает `nc -X connect -x 127.0.0.1:<port>`.
- Проверено: `ssh -V` → `OpenSSH_10.3p1`; `ssh -T git@github.com` проходит
  handshake и host key, остаётся только auth по ключу.
- Ключ сгенерирован: `~/.ssh/id_ed25519` (публичную часть добавить в GitHub).
- Осталось: `git clone git@github.com:...` после добавления ключа в аккаунт.

### Зачем
`git clone/push git@github.com:...` не работает: нет ssh-клиента.

### Что берём
Alpine `openssh-client` (musl): `ssh`, `ssh-keygen`, `scp`, `sftp` + зависимости
(`libcrypto`, `libssl`, `zlib`, `libedit`). OpenSSL-библиотеки уже вложены для git.

### Шаги
1. Извлечь бинарники и зависимости в `runtime/git/` (общий бандл с git).
2. Обёртки `files/usr/bin/ssh`, `ssh-keygen`, `scp` через musl-loader.
3. Создать `~/.ssh/` и `~/.ssh/config`:
   ```
   Host *
       StrictHostKeyChecking accept-new
       UserKnownHostsFile ~/.ssh/known_hosts
   ```
4. Проверить:
   - `ssh -V`
   - `ssh -T git@github.com` — должно дойти до GitHub (без ключа будет
     `Permission denied (publickey)`, это нормально);
   - `ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519` — сгенерировать ключ,
     публичную часть добавить в GitHub;
   - после добавления ключа: `git clone git@github.com:...`.
5. Задать `GIT_SSH_COMMAND` не нужно — `ssh` уже в `PATH`.

### Ограничения
- Пароль/passphrase интерактивно не вводится: ключ без passphrase или ssh-agent
  (агента нет).
- Host key принимается автоматически (`accept-new`) — удобно, но менее строго.

### Критерий готовности
`git clone`/`push` по SSH с ключом работают. Размер: **~1–3 МБ**.

## 2. Python (статический musl) (✅ сделано)

### Результат
- CPython **3.12.16** (python-build-standalone, musl), урезан до ~42 МБ.
- `pip 26.2.2`; установка с PyPI через встроенный прокси.
- Теги pip: `musllinux_1_1` + `musllinux_1_2` (через `sitecustomize.py`), поэтому
  ставятся готовые колёса.
- `sys.executable` указывает на shell-обёртку — дочерние процессы pip работают.
- Проверено: `python3 -V`, `pip install six`, `pip install mcp` (`mcp 2.3.0`),
  `pip install python-lsp-server` (`pylsp 1.15.0`), `import mcp`.
- Осталось (в рамках MCP): прописать Python-MCP-сервер в `opencode.json`.

### Зачем
Python-MCP-серверы и `pyright` (Python-LSP).

### Что берём
`python-build-standalone`, релиз `20261026`:
`cpython-3.12.16+20261026-aarch64-unknown-linux-musl-install_only_stripped.tar.gz`
(27.0 МБ). Кладём в `runtime/python/`, распаковываем в `files/usr/python`.

### Шаги
1. Скачать и распаковать в `runtime/python/`.
2. Обёртки `files/usr/bin/python3`, `pip`:
   ```sh
   PY=/data/user/0/ru.opencode.android/files/usr/python
   export PYTHONHOME=$PY
   exec <loader> --library-path "$PY/lib:<lib>" "$PY/bin/python3" "$@"
   ```
3. Проверить `python3 -V`, `python3 -m pip -V`, `pip install`.
4. Запустить простой Python-MCP-сервер, прописать в `opencode.json`.
5. При необходимости — `pyright` как LSP.

### Ограничения
- Нативные pip-колёса под glibc не подойдут; нужны musllinux/aarch64 или pure-Python.
- `_ssl`/`_hashlib` требуют OpenSSL — библиотеки уже есть, проверить импорт.

### Критерий готовности
Python-MCP-сервер запускается и его инструменты доступны. Размер: **~27 МБ**
(в APK сжато меньше).

## 3. Node/Bun-обёртки + MCP (✅ сделано)

### Результат
- `node`, `bun`, `npx`, `bunx` через встроенный Bun (`BUN_BE_BUN=1`).
- `npx`/`bunx` — шим: `bun add` в кэш + запуск `.bin` через `node`
  (обход `process.execPath` = loader).
- Remote MCP `context7` и локальный `everything` — оба `connected` в `/api/mcp`.
- Проверено: `node -e`, `bun --version`, `npx -y cowsay`,
  `npx -y @modelcontextprotocol/server-everything` (initialize-ответ).

### 3a. Node/Bun-обёртки
Внутри opencode уже есть Bun. Добавить `node`, `npx`, `bun`, `bunx`:
```
BUN_BE_BUN=1 <loader> ... <opencode> "$@"
```
`npx` → `opencode x`. `HTTPS_PROXY` берётся из `files/.proxy`.
Проверить `node -e`, `npx -y @modelcontextprotocol/server-everything --help`.

### 3b. Локальные MCP
`opencode.json`:
```json
"mcp": {
  "everything": {
    "type": "local",
    "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
    "enabled": true
  }
}
```

### 3c. Remote MCP (встроено в OpenCode)
```json
"mcp": {
  "my-remote": {
    "type": "remote",
    "url": "https://...",
    "enabled": true,
    "headers": { "Authorization": "Bearer ..." },
    "oauth": false
  }
}
```
Сеть идёт через прокси (`HTTPS_PROXY`).

### Критерий готовности
JS-MCP-сервер стартует, инструменты доступны; remote MCP подключается.
Размер: **+0 МБ** (обёртки), пакеты MCP качаются по сети.
