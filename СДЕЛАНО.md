## Английский интерфейс — 1.14.0 (2026-11-09)

- **Добит английский на всех основных экранах.** Проверено на телефоне:
  чат (инструменты, размышления, asks, вложения), файловый проводник и

  использование/тарифы, обновление, онбординг, нативные настройки, тосты и
  диалоги.
- **Динамические подписи чата** переведены через `T()`; `#msgs` не проходит
  авто-перевод, поэтому раньше часть подписей оставалась русской.
- **Исправлен важный баг языка:** `tr()`/`__t` переводили строки даже при
  русском языке, из-за чего в чате появлялись английские «Show earlier»,
  «Model switched», «Reasoning» и английские тосты. Теперь при `lang=ru`
  строки возвращаются как есть.
- **Длинные фразы** переводятся как подстроки (`LONG` в `i18n.js` и
  `Lang.tr`), поэтому склеенные заметки/инструкции не остаются наполовину
  русскими.
- **Пользовательские данные не переводятся:** названия чатов, имена файлов
  и папок, пути, названия моделей помечены `data-noi18n`.
- **Нативные тосты/диалоги** обёрнуты в `Lang.tr`: `SettingsActivity`,
  `AppUpdater`, `RuntimeService`, `Notifications`, `MainActivity`, `Updater`,
  `OnboardingActivity`.
- **Исправлены остатки ПК-моста:** «OpenCode Remote» → «OpenCode»,
  «загрузится на компьютер» → «прикрепится к сообщению», «удалится с
  компьютера» → «с телефона», убраны устаревшие «обновите до 1.5» и
  «нужно 1.4».
- **Исправлен латентный краш** `t is not a function` в `bridge.js`: локальная
  переменная `t` перекрывала функцию перевода, и чат с вложением без имени
  мог не загрузиться (тост «Could not load chat»).
- Даты в статистике использования форматируются по языку (`en-US`/`ru-RU`).
- **Релиз `v1.14.0` опубликован** на GitHub Releases: APK 199 741 853 байт,
  SHA-256 `226022e3405577d3e5b52b3397722d2a5f1b9193e7e9d579caa41738d256626f`,

## Веб-поиск — 1.11.0 (2026-11-09)

- Новая вкладка ⚙ Настройки → **«Веб-поиск»**: Exa, Firecrawl, Parallel,
  Tavily, TinyFish. Видно активного провайдера и наличие ключа.
- **Выбор** пишется в `~/.config/opencode/opencode.json` как
  `websearch: {provider: "<id>"|"random"}`; OpenCode перечитывает конфиг
  на лету. Добавлен `POST /android/occonfig` (Java), который меняет только
  этот ключ и не трогает остальные настройки.
- **Ключи** вводятся в карточке провайдера и сохраняются в OpenCode
  (`POST /api/integration/{id}/connect/key` → `/api/credential`), не в prefs
  и не в HTML. У TinyFish ключ не нужен.
- **Проверить** делает `POST /api/websearch` с тестовым запросом и показывает
  три ссылки; без ключа — понятная ошибка.
- Проверено на телефоне: переключение tinyfish/random/авто (OpenCode сразу
  отвечает выбранным), «Проверить» — 8 результатов, Tavily без ключа —
  ошибка за ~6 с, ключ Tavily создаётся/удаляется; после теста конфиг и
  креды очищены. `smoke_test.py` — 8/8, версия 1.11.0.

## Надёжность без потери возможностей (1.9 → 1.9.2, 2026-11-08)

- **1.9 — WebView.** Навигация разрешена только на `http://127.0.0.1:8769`
  (`isAppUrl()`: схема + host + порт). Раньше `startsWith("http://127.0.0.1")`
  пропускал `127.0.0.1.evil.com`. Внешние ссылки уходят в браузер; `file:`,
  `javascript:`, `data:`, `about:`, `blob:`, `chrome:` блокируются;
  `setAllowFileAccess(false)`. Проверено: страница и чаты работают,
  `example.com` → браузер, `127.0.0.1.evil.com` → браузер (WebView цел),
  `file:///sdcard/` блокируется.
- **1.9.1 — LocalServer.** Токен проверяется **до** чтения тела (аноним с
  `Content-Length: 200000000` получает 403, не занимая память), тело ≤ 128 МБ
  (и chunked, гигантский чанк → 413), заголовки ≤ 120 строк / 64 КБ (431),
  пул `ThreadPoolExecutor(4..64, SynchronousQueue)` вместо безлимитного
  кэша (SSE занимает поток, очередь не копится). Проверено 8 тестами на
  сырых сокетах + SSE и медиа с `?token=`.
- **1.9.2 — импорт бэкапа.** 20 000 файлов и 512 МБ (счёт по распакованным
  байтам), поток файла закрывается в `finally`. Проверено стендом: обычный
  архив, 20 050 записей и 520 МБ.
- **1.9.3 — `ocsh`.** Вывод ≤ 4 МБ на поток с пометкой «… вывод обрезан»;
  таймаут задаётся в ⚙ Настройки → «Лимит времени для shell-команд, сек»
  (0 — без лимита, по умолчанию 0). Проверено: 10 МБ `base64` → 4 194 356
  байт с пометкой; лимит 5 с остановил `sleep 40` за 5.2 с; с нулём `sleep 8`
  отработал полностью; `ocsh id` → `uid=2000(shell)`.
- **1.9.5–1.9.7 — маркер рантайма.** `build_apk.py` генерирует
  `assets/runtime/manifest.txt` (SHA-256 + размер, 4602 файла), `Runtime`
  считает маркер `m<16 hex>` от манифеста. Смена версии приложения больше не
  распаковывает 250 МБ; изменение любого runtime-файла — распаковывает.
  Проверено: 1.9.6 без изменений стартовала без распаковки, 1.9.7 после правки
  `occtl.py` — с распаковкой.
- **1.9.4 — обновления.** SHA-256 из `digest` релиза GitHub сверяется с
  скачанным архивом (несовпадение → обновление прерывается до замены
  бинарника); канал `stable`/`preview` кнопкой в ⚙ Настройки. Проверено:
  `sha256()` совпадает с `hashlib` на 190 МБ, канал переключается, проверка
  обновлений даёт «Установлена последняя версия 2.2.6».
- **Уведомления (1.6–1.8), проверено после перезагрузки:** вкл → одно «Ответ
  готов»; выкл → ни одного; приложение открыто → ни одного; ошибка → одно

## Задача

Сделать **самостоятельное Android-приложение**, которое работает как OpenCode,
но **без ПК и без моста**. Дизайн взять из `<old-project>`
(старое приложение `OpenCode Remote` + `page_chat.html`), а функционал — из
настоящего open source OpenCode.

## Что выяснилось

- Старое приложение — это WebView + `oc_server.py` на ПК; без ПК оно не работает.
- `rea-main` в рабочей папке — это **REA (reverse engineering)**, к OpenCode
  отношения не имеет. В проекте не используется.
- Установленный OpenCode — **v2.2.6** (Electron desktop + `opencode-cli.exe`).
- Исходники OpenCode: GitHub `anomalyco/opencode`, ветка `dev`
  (склонированы в `%TEMP%\opencode-src` для изучения API).
- **Главный результат проверки:** официальный `opencode-linux-arm64-musl`
  **запускается на Android 16 напрямую** через musl loader. Полный сервер
  `opencode serve` работает, модели отвечают, инструменты `write`/`shell`/`glob`
  выполняются на телефоне.
- Поэтому тяжёлый Debian + proot **не нужен**. Приложение использует нативный
  бинарник OpenCode + musl-библиотеки внутри APK.

## Архитектура (кратко)

```
WebView (page.html + bridge.js)
   → локальный HTTP 127.0.0.1:8769 (Kotlin)
      → /oc/*  → opencode serve 127.0.0.1:4096 (Basic auth)
      → /android/* → файлы телефона
      → /upload, /files, /thumb
```

- `opencode serve` запускается foreground-сервисом `RuntimeService`.
- `bridge.js` повторяет протокол `oc_server.py` (`state`, `upd`, `chats`,
  `models`, `fs`, `asks`, …), но работает напрямую с OpenCode.
- ПК не участвует вообще.

## Что реализовано

### Рантайм
- OpenCode 2.2.6 arm64 musl + musl loader + libstdc++/libgcc.
- ripgrep 15.1.0 (musl) + libpcre2 — для инструментов `grep`/`glob`.
- Распаковка из APK при первом запуске (~2 секунды), маркер версии.
- `shell: /system/bin/sh` (Android shell), `PATH` с `files/usr/bin`.
- `OPENCODE_DISABLE_FFF=1` — чтобы не грузить glibc-модуль и использовать rg.
- PID-файл и очистка осиротевших процессов; свободный порт 4096+.

### Android-приложение
- Пакет `ru.opencode.android`, minSdk 26, targetSdk 28 (как Termux — разрешает
  запуск своих бинарников из каталога приложения).
- WebView со страницей из `assets/app`, тёмный splash, автозапуск сервиса.
- Foreground-сервис + уведомление, автозапуск после перезагрузки (`BootReceiver`).
- `LocalServer`: страница, прокси `/oc`, `/android/fs`, `/android/mkdir`,
  `/android/home`, `/android/config`, `/upload` (multipart), `/files`, `/thumb`.
- `AndroidBridge`: уведомления, вибрация, копирование, открытие ссылок,
  системные настройки, выбор файла, проверка прав.
- `SettingsActivity`: рабочая папка, права на файлы, отключение оптимизации
  батареи, перезапуск, журнал, тест уведомления (ключ Zen — во вкладке «Провайдеры»).
- Токен `X-Bridge-Token` для всех чувствительных маршрутов (без него 403).
- Фоновые уведомления «Ответ готов» / «OpenCode ждёт ответа» (нативный watcher).

### Интерфейс (дизайн из старого приложения)
- `page.html` — копия `page_chat.html` с минимальными правками:
  - вместо WebSocket — `bridge.js`;
  - кнопка «панель ПК» стала шестерёнкой настроек;
  - кнопка установки APK с ПК скрыта;
  - выбор папки стартует с рабочей папки телефона;
  - ключ OpenCode Zen и вход по аккаунту — во вкладке «Провайдеры»;
  - медиа-пути понимают Android (`/storage/...`), а не только `C:\...`.
- Модель по умолчанию — `deepseek-v4.1-flash-free` (OpenCode Zen, бесплатная);
  выбор запоминается.
- Работают: чаты, переименование, удаление, выбор модели, стриминг,
  размышления, инструменты, вложения, папки, галерея, настройки.

## Как установить/пользоваться

1. Взять `OpenCodeAndroid.apk` из папки проекта.
2. Установить на телефон (разрешить установку из этого источника).
   Если `INSTALL_FAILED_VERIFICATION_FAILURE`:
   ```powershell
   adb shell settings put global verifier_verify_adb_installs 0
   adb shell settings put global package_verifier_enable 0
   adb install --no-incremental -r -d OpenCodeAndroid.apk
   ```
3. Открыть **OpenCode**. Первый запуск: разрешить доступ к файлам
   (и при желании — отключить оптимизацию батареи в настройках).
4. Рабочая папка по умолчанию: `/storage/emulated/0/OpenCode`.
5. Модель: кнопка с названием модели внизу. Бесплатные модели OpenCode Zen
   работают без ключа. Ключ (если нужен платный) — шестерёнка → «Провайдеры» →
   «Ключ OpenCode Zen».
